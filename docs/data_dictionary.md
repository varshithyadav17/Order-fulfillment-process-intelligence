# Data dictionary

All order data is synthetic and generated by `src/generate_data.py` using a fixed random seed. Values and segment relationships are illustrative, not real operational evidence.

| Field | Type | Description |
|---|---|---|
| `order_id` | String | Unique synthetic order identifier. |
| `warehouse` | Category | Synthetic warehouse assigned to the order. |
| `carrier` | Category | Synthetic delivery-carrier label. |
| `region` | Category | Synthetic destination region. |
| `product_category` | Category | Synthetic product category. |
| `order_value` | Decimal | Simulated order amount in arbitrary currency units; not loss or margin. |
| `ordered_at` | Timestamp | Order-created timestamp. |
| `packed_at` | Timestamp | Order-packed timestamp. |
| `shipped_at` | Timestamp | Carrier handoff/shipment timestamp. |
| `delivered_at` | Timestamp | Delivery timestamp. |
| `promised_delivery_at` | Timestamp | Per-order synthetic promised delivery timestamp. |
| `warehouse_processing_hours` | Numeric | Hours from order creation to packing. |
| `handoff_hours` | Numeric | Hours from packing to shipment. |
| `transit_hours` | Numeric | Hours from shipment to delivery. |
| `fulfillment_hours` | Numeric | End-to-end hours from order creation to delivery. |
| `delivery_delay_hours` | Numeric | Hours from promised delivery to actual delivery; negative means early. |
| `is_late` | Integer (0/1) | 1 if delivered after promised timestamp, otherwise 0. |
| `is_on_time` | Integer (0/1) | Complement of `is_late`. |
| `order_month` | YYYY-MM | Month of order creation. |

## Business definitions

- **Late-delivery rate** = late orders divided by all orders, multiplied by 100.
- **On-time rate** = on-time orders divided by all orders, multiplied by 100.
- **Average fulfillment time** = mean of `fulfillment_hours`.
- **Order value on late orders** = sum of order values for late orders. This is exposure context, not a calculated financial loss.
- **Stage share** in the SQL output is each mean stage duration divided by mean end-to-end duration. It may not sum to exactly 100% because of rounding.

A real implementation would need agreed business definitions for cutoff times, partial deliveries, failed deliveries, cancelled orders, timezone rules, SLA exceptions and order eligibility.
